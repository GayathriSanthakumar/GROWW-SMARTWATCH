# Deploying SMARTWATCH (getting a public demo link)

SMARTWATCH is three moving parts that must all talk to each other:

| Part | What it is | Default local port |
|---|---|---|
| **frontend** | Next.js 14 app (the UI) | `3000` |
| **backend** | Express + Socket.IO + Postgres/Redis | `4000` |
| **database** | PostgreSQL (Redis optional) | `5432` |

## ⭐ Permanent link in ~10 minutes (recommended)

This repo is already wired to run **everything from ONE Render service** — the built
frontend (static export), the Express API and Socket.IO all on a single origin, so there
are no CORS/cookie problems and only one URL to submit. A `render.yaml` blueprint is included.

1. **Database — Neon (free):** https://neon.tech → New project → copy the **pooled**
   connection string → that is your `DATABASE_URL`. (The backend migrates + seeds the demo
   account automatically on first boot when the DB is empty.)
2. **Push this repo to GitHub** (it already has an `origin`): `git add -A && git commit -m "..." && git push`.
3. **Render — one web service:** https://render.com → **New → Blueprint** and pick your repo
   (it reads `render.yaml`), or **New → Web Service** with:
   - Build command: `npm ci && npm run build`
   - Start command: `npm run start`
   - Node version: 20
   - Env: `DATABASE_URL` (Neon pooled URL), `FRONTEND_URL=https://<your-service>.onrender.com`,
     `APP_BASE_URL=https://<your-service>.onrender.com`, `NODE_ENV=production`,
     `SEED_DEMO_ACCOUNT=true`, `UNIVERSE_LIMIT=200`. JWT secrets are auto-generated by the blueprint.
4. Open **https://<your-service>.onrender.com** and log in with **demo@smartwatch.app / demo1234**.

Notes:
- Free Render spins down after ~15 min idle; the link wakes on the next visit (a few seconds
  of cold start). Keep it hot with a free UptimeRobot ping every 5 min, or upgrade (~$7/mo) for instant response.
- Everything is same-origin, so no `NEXT_PUBLIC_*` values are required (the frontend
  auto-detects the origin). The static bundle is served by the backend automatically when
  `frontend/out` exists (built by `npm run build`).

## Other ways

Two ways to get a public URL:

- **Option A — real deploy (recommended, ~15 min, gives a stable link to submit):**
  Postgres on **Neon** (free), backend on **Render**, frontend on **Vercel**.
- **Option B — instant tunnel from localhost (30 seconds, link dies when you stop it):**
  run everything locally behind one port with `scripts/demo-proxy.mjs`, then tunnel it.

---

## Option A — real deploy

### 1. Database on Neon (free)

1. Create a project at https://neon.tech (any region).
2. Copy the **pooled connection string**: `postgresql://user:pass@ep-….pooler…/neondb?sslmode=require`.
3. That URL is your `DATABASE_URL`.

### 2. Backend on Render (free)

1. Create a **New Web Service**, connect your GitHub repo (or push it first).
2. Set:
   - **Build command:** `npm ci && npm run build -w backend`
   - **Start command:** `npm run start -w backend`
3. Add the environment variables (see the table below).
4. On first boot the backend **migrates and seeds automatically** when the DB is empty
   (`migrate()` + `SEED_DEMO_ACCOUNT=true` in `backend/src/server.ts`), so you get the
   demo account + ~400 Indian stocks with zero extra steps.
   - TradingView import (`UNIVERSE_LIMIT`, default 800) also runs on boot. Lower it to
     `300` on free tiers to keep cold-starts snappy.
5. Copy the Render URL, e.g. `https://smartwatch-api.onrender.com`.

### 3. Frontend on Vercel

1. Import the same repo. Root: `/`. Framework preset: Next.js.
2. Build command: `npm run build -w frontend`; Output dir: `frontend/.next` (leave defaults).
3. Add these env vars:

| Variable | Example | Notes |
|---|---|---|
| `NEXT_PUBLIC_API_URL` | `https://smartwatch-api.onrender.com` | backend base URL |
| `NEXT_PUBLIC_WS_URL` | `https://smartwatch-api.onrender.com` | same host as API |
| `NEXT_PUBLIC_GOOGLE_CLIENT_ID` | (blank) | leave blank for demo stub |

> The frontend **auto-detects same-origin** API/socket URLs when these are unset, so if you
> ever run behind one host (or use Vercel rewrites) you can omit both variables.

### 4. Backend environment variables (Render)

| Variable | Value |
|---|---|
| `NODE_ENV` | `production` |
| `PORT` | set automatically by Render |
| `DATABASE_URL` | Neon pooled connection string |
| `FRONTEND_URL` | your Vercel app URL (CORS + Socket.IO origin) |
| `APP_BASE_URL` | your Render backend URL |
| `JWT_ACCESS_SECRET` | long random string |
| `JWT_REFRESH_SECRET` | long random string |
| `SEED_DEMO_ACCOUNT` | `true` |
| `DEMO_MODE_DEFAULT` | `true` |
| `UNIVERSE_LIMIT` | `300` (free tier) |
| `REDIS_URL` | optional — app falls back to in-memory cache |
| `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` | blank (stub flow) |
| `OPENAI_API_KEY` | blank (deterministic AI analyst) |

Cookies become `Secure` in production automatically. After both deploy, open the Vercel URL
and log in with **demo@smartwatch.app / demo1234** (or click **Try Demo Mode**).

## Option B — instant tunnel from localhost

Run everything locally first (`npm run dev` → frontend `:3000`, backend `:4000`), then in a
separate terminal start the single-host proxy and expose it with one tunnel:

```bash
npm run demo:proxy          # serves frontend + /api + /socket.io on http://localhost:8080
# in another terminal:
cloudflared tunnel --url http://localhost:8080     # recommended
# or
npx localtunnel --port 8080
# or
ngrok http 8080
```

Open the printed `https://….trycloudflare.com` (or `.loca.lt`) URL. Because everything is on
one origin, cookies, Socket.IO and the API all work without CORS setup. The URL stays live
until you stop the tunnel.

> Why a proxy? Auth uses host-scoped httpOnly cookies. Two separate tunnel hosts (one for
> `:3000`, one for `:4000`) can't share those cookies cleanly — the single-port proxy avoids
> the whole class of cross-origin cookie problems for a throwaway demo link.

## Verify your demo before submitting

1. Log in with the demo account → lands on the **Watchlist**.
2. Top bar shows a LIVE/DELAYED/DEMO badge and the feed source (TradingView vs Simulator).
3. The Index strip and watchlist prices tick every ~3s.
4. Open a stock (slide-over): AI summary, chart, live tick, per-instrument status badge
   (LIVE / DELAYED / STALE / CONFLICT), and **"What changed since last view"**.
5. On the watchlist, the **"Since you were last here"** hub lists detected changes
   (price moves ≥2%, volume ≥1.5×, attention shifts ≥15 pts). Click **"✓ I've reviewed these"**
   to baseline everything and start fresh — this is the "return later and see what changed" loop.
6. Bell icon shows live unread change/alert notifications (updates over Socket.IO).
7. Demo Control Center (avatar menu → Demo Control) can inject STALE/CONFLICT scenarios.

## If you deploy to a fresh database but still want the demo data

The backend auto-seeds on an empty DB. To force a full reseed on an existing DB:

```bash
DATABASE_URL="postgresql://…" npm run db:migrate -w backend
DATABASE_URL="postgresql://…" npm run db:seed -w backend
```

`npm run db:reset -w backend` (drop + migrate + seed) is the "restore to pristine demo" button.
